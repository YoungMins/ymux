Windows と macOS 向けの軽量な tmux スタイルのターミナルマルチプレクサ。

https://github.com/user-attachments/assets/705fff59-0bda-4460-a87f-d7ba6f50993a

ymux は 1 つのウィンドウを必要な数のターミナルに分割し、レイアウトをワークスペース
ごとに保存して、シェル、スクロールバック、AI コーディングエージェントを整理して
くれます。Tauri 2 (Rust) と xterm.js で構築され、Windows では WebView2、macOS では
WKWebView 上で動作します。

## インストール

### Windows

**Microsoft Store**:
<https://apps.microsoft.com/detail/9N20Z9NKD2Q1>。Store 版はシステムの Evergreen
WebView2 ランタイム (Windows 11 に組み込み済み、Windows 10 では Windows Update で
配布) を使用し、`ymux` アプリ実行エイリアスを登録するので、どのターミナルからでも
`ymux` を実行できます。

**MSI**: [Releases](https://github.com/YoungMins/ymux/releases) から
`ymux_*_x64_en-US.msi` をダウンロードして実行してください。インストーラは
WebView2 ブートストラッパを同梱し、インストール先を `PATH` に追加するので、
どのターミナルからでも `ymux` を起動できます。

### macOS (Apple Silicon、macOS 11+)

[Releases](https://github.com/YoungMins/ymux/releases) から
`ymux_*_macos_aarch64.dmg` をダウンロードして開き、ymux を Applications へ
ドラッグしてください。

アプリは ad-hoc 署名のみで、**公証 (notarization) はされていません**。そのため
初回起動時に Gatekeeper が「破損している」または「開発元を確認できない」として
起動を拒否します。ダウンロード隔離属性を一度だけ解除してください:

```sh
xattr -dr com.apple.quarantine /Applications/ymux.app
```

## 機能

### ターミナルとレイアウト

- **永続化されるレイアウト**: 再帰的な水平 / 垂直分割。各ペインは自分のシェル、
  `cwd`、任意の起動コマンドを記憶します。
- **ペインタブ**: `Ctrl+Shift+T` でフォーカス中のペインにタブを追加します。
  非表示のタブも動き続けます。
- **カレントディレクトリの継承**: ペインを分割すると、新しいペインは起動時の
  ディレクトリではなく、親シェルが現在いるディレクトリで開きます (OSC 7 追跡)。
- **シェル自動検出**: Windows では `cmd.exe`、Windows PowerShell、
  PowerShell 7 (`pwsh`)、Git Bash、WSL ディストリビューション、そして `vswhere`
  が見つけたすべての Visual Studio の Developer Command Prompt / Developer
  PowerShell を検出します。
  macOS ではログインシェルに加え、見つかった zsh / bash / fish (Homebrew 版を
  含む) を提示します。zsh と bash は自動生成される shim 経由で起動され、shim は
  ユーザー自身の dotfile を先に読み込んでから OSC 7 フックを追加します。
- **永続スクロールバック**: 各ペインのバッファが (色も含めて) 次回起動時に薄い
  *「セッション復元」* 区切り線の下に復元されます。**設定 → 一般** で切り替え
  可能。
- **ペインのズーム、名前変更、検索**: `Ctrl+Shift+Z` で他のペインをすべて隠し、
  `Ctrl+Shift+R` でフォーカス中のペイン名を変更し、`Ctrl+F` でターミナルに検索
  バーを開きます (Enter / Shift+Enter で一致箇所を移動)。
- **プロンプトの下端固定**: 出力がペインより短いとき、プロンプトは下端に固定され、
  出力は上に向かって伸びます。デフォルトでオンで、**設定 → 一般** でオフにできます。
- **クリック可能なリンクとパス**: `Ctrl+クリック` で `http://` / `https://` リンクは
  デフォルトブラウザで、コマンドが出力したファイルパスは OS の既定のプログラムで
  開きます。実行ファイルやスクリプトは実行されず、ファイルマネージャーで表示される
  だけです。
- **テキストと画像の貼り付け**: `Ctrl+V` でテキストを貼り付けます。クリップボードに
  画像がある場合 (例: `Win+Shift+S` のスクリーンショット)、自動クリーンアップ
  される一時ファイルに保存し、引用符で囲んだパスを代わりに入力します。24 時間後に
  削除されます (`paste_image_retention_hours`)。
- **ファイルのドラッグ＆ドロップ**: ファイルやフォルダーをターミナルにドロップすると、
  引用符で囲んだパスがカーソル位置に入力されます。Enter を押すまで何も実行されません。
- **ペインごとの設定 (⚙)**: 任意の背景色と HotKey ボタン (ターミナル上のラベル付き
  ボタンに単一行または複数行のコマンドを割り当て) を設定できます。
- **トレイに閉じる**: ウィンドウを閉じると ymux はトレイ (Windows の通知領域 /
  macOS のメニューバー) に隠れ、すべてのシェルとエージェントは動き続けます。
  トレイアイコンをクリックするか ymux をもう一度起動すると再表示されます (ymux は
  同時に 1 つだけ動きます)。終了はトレイメニュー、macOS の `Cmd+Q`、またはコマンド
  パレットの **ymux を終了** で行い、未保存のエディターがあれば先に確認します。

### ワークスペース

- **番号付きワークスペース**: `Ctrl+Alt+1` .. `Ctrl+Alt+9` で最初の 9 つを切り替え
  ます。ワークスペースパネルの `+` ボタンで追加し、行の `×` で削除します (最後の
  1 つは削除不可)。ワークスペースごとに独自のレイアウトを保存し、切り替えてもペイン
  は生き続けるため、REPL や tail が死ぬことはありません。
- **ワークスペースパネル**: 左側の折りたたみ可能でスクロールできる一覧です。名前を
  ダブルクリックで変更し、行をドラッグして並べ替えます。アクティブなワークスペース
  には枠線が付きます。
- **ワークスペースごとのノート**: 各ワークスペース番号の隣にあるノートボタン、および
  アクティブなワークスペース用の `Ctrl+Alt+N`。`localStorage` に保存されます。
- **Git worktree ペイン**: コマンドパレットの **「新しい git worktree でペインを
  開く」** がブランチ名を尋ね、worktree を作成して (デフォルトの場所: 隣の
  `.ymux-worktrees/<branch>` ディレクトリ、`worktree_base_dir` で変更可能)、その中で
  ターミナルを開きます。ペインを閉じるとき、またはワークスペースを削除するときに
  worktree の削除を確認します。ブランチやコミットには一切触れません。

### AI エージェント

- **エージェント状態を一目で**: 各ターミナルペインが出力の活動とベル / OSC 9 完了
  シグナルから待機 / 実行中 / 完了 / 要注意の状態を示し、色付きのペイン枠線と
  ワークスペース行の色調で表示します。見ていない場所で CLI が終わると OS 通知と
  短いビープ音で知らせます (設定でオフにできます)。
- **ランチャー**: 上部の **+** メニューに、インストール済みのエージェント CLI、
  シェル、GUI ペインが並びます。**エージェントを再検出** を選ぶと一覧を更新します。
- **エージェントツリー**: ワークスペースパネルに、すべてのペインとタブが、そこで動いて
  いるエージェントと共に一覧表示されます。フックで検出する Claude Code セッションと
  サブエージェント、および軽量なプロセススキャンで検出する Codex、Gemini、aider
  などの他の CLI です。行をクリックすると該当ペインにジャンプします。
- **セッションの再開**: Claude Code や Codex が動いているペインで ymux を再起動する
  と、同じ会話を再開します: `claude --resume <id>
  --dangerously-skip-permissions` (すでに承認した内容を再度承認しなくて済むよう常に
  付与されます) または `codex resume <id>`。セッションが最後に活動してから 24 時間
  以内の場合に対象となります。エージェント追跡をオンにしていなくても動作し、CLI
  自身がディスクに残す記録を読み取って見つけます。シェルのみのペインは引き続き
  スクロールバックを復元します。
- **Claude Code フック追跡** (デフォルトはオフ、**設定 → 一般**):
  `~/.claude/settings.json` と、すべてのアカウントの Claude フォルダにユーザー
  レベルの HTTP フックを追加します (下の「複数アカウント」を参照。まだ存在しない
  フォルダは、その中でターミナルが起動するまでスキップされます)。オンの間は、
  ymux の外のセッションも含め、これらのフォルダを使うこのマシンの *すべての*
  Claude Code セッションがフックイベント (プロンプト、ツールの入力と出力) を
  `127.0.0.1` の ymux のポートへ送ります。ymux は自分のペイン以外から来たイベントを
  無視し、追跡をオフにするとすべてのフォルダからフックが削除されます。追跡がオンの
  まま ymux が起動していないと、Claude Code はそれらのフックの失敗を報告する
  (例: "Stop hook error occurred") ため、ymux をアンインストールする前、アカウント
  を削除する前、またはアカウントに対応しない旧バージョンに戻す前に、追跡をオフに
  してください (そうしないとアカウントのフォルダにフックが残ります)。ymux は補助
  バイナリを同梱しません。

#### 自動継続 (Claude Code)

ターミナルごとに、ペインの ⚙ ダイアログまたはコマンドパレット
(「このペインの自動継続を切り替え」)でオンにします。オンにするとペインのタイトルに
**AUTO** バッジが表示され、マウスを重ねると直近の回答が一覧されます。オンの間、
ymux が Claude Code の選択式の質問(`AskUserQuestion`)に自分で答えます。ラベルが
「(Recommended)」で終わる選択肢を選び(複数選択の質問では該当するものすべて)、
推奨の選択肢がない質問が 1 つでもあれば、その質問を拒否して Claude 自身に選ばせます。
Claude Code のフック追跡(設定 → 一般)が必要で、Claude Code 専用、実行中のみ有効です。
再起動やターミナルを閉じるとオフに戻ります。注意: 推奨の選択肢は Claude の提案に
すぎず常に正しいとは限らないため、誤答を取り消しやすい作業でのみ使ってください。

#### オフィス表示

上部バーのオフィスボタン（または `Ctrl+Shift+O`）で、現在のワークスペースをピクセル
アートのオフィスとして表示します。ペイン（またはタブグループ）は分割したとおりの配置で
部屋になり、部屋の間には廊下ができ、タブごとに机が置かれます。エージェントは CLI の色の
スライムです（Claude Code はオレンジ、Codex は濃いグレー、Gemini は青）。作業中は机で
ぷるぷる揺れて使っているツールを吹き出しに表示し、対応が必要なときは背伸びして跳ね、
完了するとコーヒーを飲み、待機中はとろけて昼寝します。サブエージェントは芽の生えた小さな
スライムとして入ってきて前列で作業し、終わるとリードに報告して出ていきます。

上部のテーマ選択で、同じ配置をオフィス・洞窟・城・牧場・宇宙ステーション・海底・雪の村・
砂漠の神殿に切り替えられます。机は石板・干し草・コンソールなどになり、その上の水晶・
ランタン・画面がペインの状態に合わせて光ります。選んだテーマは記憶されます。

**冒険者。** アカウントごとに RPG の勇者になります。使用量ビューのアカウント別全期間トークン
合計（Claude Code と Codex の合算）が経験値で、1 億トークンごとに 1 レベル上がります。
オフィス上部の *⚔ 冒険者* で冒険者ギルドが開き、アカウントごとのレベル・経験値バー・職業
（戦士・魔法使い・盗賊・僧侶・ネコ）と外見（スライムか人間の冒険者。髪はエージェントの色）を確認・選択できます。オフィスのエージェントはその
アカウントの職業装備とレベルバッジを身につけ、レベルで姿が変わります。Lv 1 から初期装備、
Lv 5 から本装備、Lv 10 から宝石、Lv 25 から黄金装備、Lv 50 から翼と光るオーラ。オフィス表示中に
レベルが上がるとバナーでお知らせします。

- **完了** — エージェントがバンザイジャンプして紙吹雪が舞い、そのペインを開くまで部屋の
  前に旗が立ちます。
- **郵便** — ymux がある場所から別の場所へ渡す作業（ファンアウトのプロンプト、変更
  レビューのコメント、コミット依頼）は廊下を通って届けられ、部屋の郵便受けに入ります。
  着手前は封をした手紙、作業中は開いた手紙で、そのターンが終わると消えます。郵便受けに
  マウスを乗せると中身が見えます。
- **掲示板** — ロビーのコルク掲示板に、完了と受け渡しのたびにメモが貼られます。クリック
  で一覧が開き、項目をクリックするとそのペインへ移動します。

部屋・机・スライムをクリックすると、その場にターミナルのウィンドウが開いて画面をリアルタイムで
見られます。メニューに答えるキーボタン（矢印・Enter・Esc・Tab・1–3）とプロンプト入力欄
（Enter で送信、Shift+Enter で改行）があります。部屋をダブルクリックするか *ターミナルを開く*
でそのペインへ移動し、旗・郵便受け・掲示板のメモは直接移動します。`Esc` はまずウィンドウを、
もう一度でオフィスを閉じます。ターミナルはその間も動き続けます。旗・郵便・掲示板はアプリを
起動している間だけ保持されます。

#### 複数アカウント

Web サイトで複数のアカウントにログインするように、Claude Code や Codex のログインを
複数並行して使えます。上部バーの **+** から Claude Code か Codex を選ぶと、どの
アカウントで起動するかを尋ねます — 既定のログイン (`~/.claude`、`~/.codex`)、追加済みの
アカウント、または **+ アカウントを追加…**。新しいアカウントは名前を付けるだけで、ymux が
設定フォルダの下にアカウント専用のログインフォルダを作り、そのアカウントで初めて起動
したときにエージェントがサインインを求めます。**設定 → アカウント**では名前・色の変更と
削除ができます (既存のログインフォルダを指定するには「詳細」を開きます)。アカウントを
削除すると ymux がそのアカウント用に作ったログインフォルダも削除されるため、追加し直すと
もう一度サインインが必要です。手動で指定したフォルダは決して削除しません。アカウントは
ペインの ⚙ ダイアログでターミナルごとに選ぶか、ワークスペースパネルの行を右クリックして
ワークスペース全体の既定にすることもできます。アカウントが適用されたターミナルはタイトルに色付きのバッジが付きます。
変数はターミナルの起動時に設定されるため、変更は以降に起動するターミナルに反映
されます (実行中のシェルは元のアカウントのままで、再起動するまでバッジは薄く
表示されます)。トークン使用量は設定済みのすべてのアカウントのフォルダを読み、
セッション再開は端末が動いていたアカウントのフォルダを探します。

#### 変更をレビュー

エージェントの作業を diff として読み、行ごとのコメントをそのままエージェントに
送れます。コマンドパレットの **「変更をレビュー」**、Git ペインの **変更をレビュー**
ボタンや worktree の行、ファンアウト比較画面の **レビュー** から開きます。1 つの
リポジトリ (または worktree) を対象にした全画面のオーバーレイで、Esc または ✕ で
閉じます。隠している間も保持され、レイアウトには何も保存されません。

- **ファイルと hunk**: 左に変更されたファイルの一覧、右に選択したファイルの hunk を
  **統合** または **分割** 表示で示します。未追跡ファイルは追加として表示され、
  バイナリファイルには印が付き、非常に大きな diff は切り詰められます (3000 ファイル、
  1 ファイルあたりパッチ 512 KiB)。
- **比較対象**: `HEAD` (未コミットの変更すべて、デフォルト) またはブランチ (merge-base
  との比較)。**CR を無視** は CRLF だけの差分によるノイズを隠します。ウィンドウに
  フォーカスが戻ったときと、エージェントが終わったときに更新されます。
- **コメント**: 行をクリックしてコメントし、Shift+クリックで範囲を広げます。コメントは
  オーバーレイの中だけに存在し (閉じると破棄)、コードが動いて位置が分からなくなった
  場合は、別の行を指す代わりに「移動済みまたは削除済み」と表示されます。
- **エージェントに送信**: コメントを (それぞれファイル、行番号、前後数行つきで) その
  リポジトリで動いているエージェントのターミナルに貼り付けます。複数のエージェントが
  該当する場合は選びます。**「送信後に Enter を押す」にチェックした場合のみ** Enter も
  押し、デフォルトはオフです。エージェントが権限確認やフォルダ信頼の確認への回答を
  待っているとき、またはターミナルが貼り付けを受け付けないときは貼り付けず、
  エージェントがまったくいない場合は代わりにクリップボードにコピーします。32 KiB
  を超える場合は先に確認します。

#### 受信トレイ (対応が必要なペイン)

ワークスペースバーのベルには、対応が必要な (エージェントが質問した、または承認を
求めている) ペイン、および席を外している間に終わったペインの数がバッジで表示されます。
クリックすると一覧 (対応が必要なものが先) と、既読の直近 20 件が表示され、行を選ぶと
そのペインへ移動します。`Ctrl+Shift+U` は対応が必要な次のペインへ直接移動します。
ペインにフォーカスすると既読になります。

#### ファンアウト

1 つのプロンプトを複数のエージェントに、それぞれ専用の git worktree で実行させ、
結果を比較します。コマンドパレットから **「プロンプトを複数のエージェントに送る…」**
を実行します。

| 項目 | 意味 |
|------|------|
| リポジトリ / ベースブランチ | worktree の分岐元 |
| エージェント | 1〜8 レーン。それぞれ Claude Code または Codex で、アカウントも選べます |
| ブランチのプレフィックス | デフォルトは `fanout`。ブランチ名は `<プレフィックス>/<実行ID>-<エージェント>-<番号>` |
| プロンプト | 最大 32 KiB、すべてのレーンに渡されます |
| 新しいワークスペースで開く | レーンを新しいワークスペースに配置 |
| Enter を自動で押す | デフォルトはオン。オフならプロンプトを入力するだけで Enter は自分で押します |

レーンごとに新しいブランチと worktree (worktree ペインと同じ場所。`worktree_base_dir`
を指定しなければ `.ymux-worktrees`) が作られ、通常のエージェントコマンドを実行する
ターミナルが開きます。ファンアウトは権限バイパスのフラグを **追加しません**。レーンが
2 つなら左右に並べ、4 つまではグリッド、それ以上はタブに配置します。プロンプトは
エージェントの準備ができてから貼り付け、コマンドラインには載せません。エージェントが
フォルダ信頼の確認などの質問を出した場合、そのペインで答えるまでそのレーンは待ちます。
90 秒たっても準備ができなければ **今すぐ送信** または **プロンプトをコピー** を選べます。
起動に失敗したレーンは報告され、すでに作ったものはそのまま残ります。

**「ファンアウトのレーンを比較…」** は、レーンごとの状態、変更ファイル (+/−)、先行
コミット数を表示し、**レビュー** (ファンアウトのベースとの diff を開く)、**ペインへ
移動**、**残す…** を備えています。残すはマージを行いません。マージコマンドを示して
メインの worktree に入力するだけで (実行は自分で)、残りのレーンの整理を提案します。
整理は確認した worktree を削除し、ブランチは `git branch -d` で削除するため、
マージされていないブランチは残ります。

### アクティビティログと通知

任意の機能で、**デフォルトはオフ**です: **設定 → アクティビティと通知**。ymux は
エージェントの作業をローカルのログに残し、ターンが終わったときやエージェントが
あなたを必要としたときに、チャットや Webhook へ短い報告を送れます。モデルのトークンは
消費せず、送信先を追加しない限り PC の外には何も出ません。

**記録するもの。** プロンプト、ツール呼び出し、権限リクエスト、終了したターンごとに
JSON を 1 行。Claude Code のイベントは上記のフック追跡から来るため、フック追跡が
オンである必要があります。Codex のターンは CLI 自身のセッションファイルから、ymux が
すでに追跡しているターミナルについてのみ読み取ります。ツールの記録には、ツール名、
触れたファイルのパス (切り詰め)、切り詰めたコマンドライン、終了コードが残ります。
終了したターンには、所要時間、`git diff --stat` から得た変更ファイルと +/− の数、
テストの合否が加わります。**記録しないもの**: ファイルの内容、ツールの出力、会話の
全文、そして **プロンプト本文を記録** をオンにしない限りプロンプトとアシスタントの
返答テキスト。

**マスキング。** ディスク、要約器、Webhook に渡る前にすべてマスクします。対象は
秘密鍵ブロック、ベンダーのトークン (`sk-…`、`ghp_…`、`xox…`、AWS・Google のキー)、
JWT、`Bearer` ヘッダー、`user:pass@` 形式の URL、チャットの Webhook URL、`key=value`
形式の秘密値です。パターンマッチであり、完全性は保証しません。

**保存。** ymux の設定ディレクトリ ([設定](#設定) を参照) の
`activity/YYYY-MM-DD.jsonl` に、1 日 1 ファイルで保存します。ログは 14 日後に削除され
(**ログの保持**)、全体は 200 MiB (`max_total_mb`)、1 日は 20 MiB が上限で、超えた場合は
ツールの記録から捨てます。**ログフォルダを開く** と **ログを消去** は同じセクションに
あり、このセクションでは最近のターンも確認できます。

**要約。** ターン終了時に上記の事実情報から作成し、会話の全文からは作りません。

- **組み込みルール** (デフォルト): モデル不要でオフラインで動作します。英語、韓国語、
  日本語のテンプレートがあります (他の言語は英語)。
- **Ollama**: **モデルを読み込む** で取得済みのモデルを一覧して選びます。小さな
  モデルで十分です。[Ollama](https://ollama.com) をインストールしたうえで、例えば:

  ```sh
  ollama pull gemma3:1b
  ```

  デフォルトのエンドポイントは `http://127.0.0.1:11434` です。
- **OpenAI 互換** (LM Studio など): エンドポイント、モデル、API キー。キーは暗号化
  して保存され、再表示されません。

エンドポイントはこのコンピューター上にある必要があります。名前を解決したあとのアドレス
を検査するため、別の場所を指す名前は拒否されます。**リモートエンドポイントを許可** を
オンにすると制限が外れ、以降はターンのテキストがそのサーバーに送られます。リクエストは
デフォルトで 20 秒でタイムアウトし、失敗した場合は組み込みルールの要約に切り替わります。
**要約をテスト** でモデルの返答を確認できます。

**Webhook の送信先。** 好きなだけ (最大 20 件) 追加でき、それぞれ個別に設定します。

| 形式 | 備考 |
|------|------|
| JSON (汎用) | 署名付き (後述)。ファイルを添付すると multipart |
| Slack | 受信 Webhook のブロック。添付ファイルは名前のみ一覧表示 |
| Discord | 埋め込み。ファイルは Discord のサイズ制限内で最大 10 個アップロード |
| Microsoft Teams | Workflows のアダプティブカード。添付ファイルは名前のみ一覧表示 |

送信先ごとの設定: 有効、名前、URL、イベント (**ターン完了**、**対応が必要**)、詳細度
(**要約** または **詳細**: ペイン、アカウント、作業フォルダ、ファイル、テスト結果を追加)、
**プロンプトを含める** (オフ)、まとめ送信の待機時間 (デフォルト 10 秒、1 通に最大 10
イベント)、任意の HMAC 秘密値。**テスト送信** と **ペイロードをプレビュー** で送られる
内容を確認できます。配信に失敗するとディスク上のキュー (送信先ごとに 200 件または
5 MiB) に積み、バックオフで再試行します (5 秒から倍々で最大 30 分、8 回、`Retry-After`
を尊重)。リダイレクトは辿りません。**Webhook の URL は認証情報です**。持っている人は
誰でもそのチャンネルに投稿できるため、ymux は URL、秘密値、API キーを `config.toml`
ではなく `secrets.json` に暗号化して (Windows は DPAPI、macOS は `0600` のファイル)
保存し、再表示しません。`http://` の URL は、報告が暗号化されずにネットワークを通る
ため警告が表示されます。

JSON 形式の検証。リクエストごとに `X-Ymux-Timestamp` (Unix 秒)、`X-Ymux-Delivery`
(一意の ID) が付き、秘密値を設定している場合は `X-Ymux-Signature: sha256=<hex>` も
付きます。値は `hex(HMAC-SHA256(秘密値, タイムスタンプ + "." + 本文))` です。multipart
のリクエストでは、最初のパートである `payload` が署名対象の本文です。

```python
import hmac, hashlib

def verify(secret: str, timestamp: str, body: bytes, signature: str) -> bool:
    mac = hmac.new(secret.encode(), timestamp.encode() + b"." + body, hashlib.sha256)
    return hmac.compare_digest("sha256=" + mac.hexdigest(), signature)
```

現在時刻から大きく外れたタイムスタンプや、重複した配信 ID も拒否してください。

**添付ファイル。** 送信先ごとの設定で、デフォルトはオフです。ターンが生成したファイルを
報告と一緒に送ります。候補は、ターン中にそのターミナルのリポジトリ (または worktree)
内で作成・変更されたファイルと、ターン中にレポートフォルダ (デフォルトは
`.ymux/report`、**レポートフォルダ**) に置かれたファイルです。許可する種類は自分で
選び (デフォルトはなし)、画像 (png、jpg、gif、webp)、PDF、音声 (mp3、wav、ogg)、
動画 (mp4、webm)、Office 文書 (docx、xlsx、pptx)、テキスト (md、txt、csv) です。既定の
上限は 1 ファイル 8 MB、合計 8 MB、4 ファイル (最大値は 25 MB、10 ファイル)。通常の
ファイルで、シンボリックリンクではなく、ハードリンクが 1 つだけで、内容が拡張子と一致し
(秘密値を含むテキストファイルは拒否)、名前が機密扱いではない (`.env*`、`*.pem`、
`*.key`、`id_rsa*`、`*secret*`、`*credentials*` など、または `.git`、`.ssh`、`.aws` の
配下ではない) ファイルだけを送ります。送信の瞬間に、開いたファイルを基に再度検査
します。条件に合わないファイルや上限を超えたファイルは名前のみ一覧表示され、それが原因で
配信全体が失敗することはありません。

**旧バージョンへ戻す場合。** 0.13.9 以前のバージョンはこの機能を知りません。それを
開くと `config.toml` の Webhook 一覧が消えるため (暗号化された秘密値は `secrets.json`
に残ります)、送信先の設定を事前に控えておいてください。

### サイドパネル: ファイルと使用量

すべてのワークスペースで共有される、右側のパネルが 1 つあります。上部のアイコンで
2 つの画面を切り替え、非表示の間もそれぞれの状態を保持します。開閉状態、画面、幅は
保存され、左端をドラッグして幅を変更できます。

- **ファイル**: `Ctrl+Shift+E` で切り替えます。`cd` に合わせてアクティブなペインの
  作業ディレクトリに追従します。ファイル上で Enter を押すと再利用されるエディター
  タブで開き、一覧の下に選択中のファイルやフォルダーのプレビューが表示されます
  (`Tab` で表示 / 非表示)。
- **使用量**: パネルの使用量アイコンで切り替えます (ツールバーのサイドパネルボタンは最後の画面を
  再び開きます)。コマンドパレットからも開けます。次の内容を表示します:
  - Claude Code と Codex のローカルトークン数。セッションログから読み取り、過去
    5 時間、過去 7 日、または全記録の期間を、AI プロバイダー、モデル、プロジェクト、
    アカウント別にまとめ、選択した期間の合計行を表示します (**全記録の使用量** では
    総合計)。
  - 5 時間 / 週間の残り利用枠とリセットまでのカウントダウン。残りまたは使用済みの
    好きな方で表示できます。利用枠は、それらの CLI がすでに PC に保存しているサインイン
    トークンを使い、Anthropic と OpenAI から直接取得します ([プライバシー](#プライバシー)
    を参照)。

  ローカル合計は表示中 10 秒ごとに更新され、アカウントの利用枠は最大でも 1 分に 1 回だけ
  取得します (失敗時はより早く再試行し、↻ ボタンは最大 30 秒ごと。それ以外は前回の結果を
  表示します)。ローカル合計にはウェブチャットや他の端末は含まれず、
  以前使っていたアカウントが含まれる場合があるため、契約の利用枠とは一致しません。
  利用枠を取得できないときは、記録済みのスナップショットが古い情報として表示されます。

### 内蔵ペイン

ターミナルと並んで ymux 自身が描画する画面です。いずれもフォーカス中のペインを分割し、
その作業ディレクトリで開きます:

- ターミナルの右クリックメニュー: ファイル、エディター、Git
- 上部バーの **+** ランチャー: ファイル、Git、ブラウザ (**+ ブラウザ** ボタンでも追加可)
- コマンドパレット: **分割: ファイルペイン**、**分割: エディターペイン**、
  **分割: git ペイン**

エディターはサイドパネルでファイルを選んで Enter を押しても開きます。

| ペイン | 機能 |
|--------|------|
| **ファイル** | 閲覧、プレビュー、名前変更、新規作成、複数選択、コピー/移動、上書き確認、ごみ箱へ削除 (確認あり) |
| **エディター** | シンタックスハイライト付きテキストエディター: 保存、検索/置換、行へ移動、CRLF/BOM 保持、未保存の変更の確認、クラッシュ対策の下書き保存、外部変更の検出 |
| **Git** | コミットグラフ、ブランチ一覧とチェックアウト、worktree の追加/削除 (確認あり)、**変更をレビュー** (diff レビュー) |
| **ブラウザ** | URL バーと 戻る / 進む / リロード を備えた iframe ブラウザ。URL は切り替えや再起動を越えて保持されます |

> **注意:** ブラウザペインは HTML `<iframe>` なので、`X-Frame-Options` や CSP
> `frame-ancestors` で埋め込みを拒否するサイト (例: github.com、google.com) は
> 読み込めません。ローカル開発サーバー、Storybook、社内ダッシュボード、ドキュメント
> 向けで、一般的な Web ブラウジング用ではありません。

### 生産性

- **コマンドパレット**: `Ctrl+Shift+P`。名前やキーバインドで内蔵の操作をファジー
  マッチで検索できます。**タブの名前を変更**、**他のタブを閉じる**、**新しい
  ワークスペース**、**ワークスペースを削除**、ワークスペース名の変更、エディター /
  ファイル / git ペインの分割など、パレットでしか使えない操作もあります。
- **システムモニター**: 下部のステータスバーに CPU / RAM / GPU / ディスク /
  ネットワークを 2 秒ごとに表示します。70% で橙、90% で赤に変わります。
- **アップデート通知**: 6 時間ごとにバックグラウンドで GitHub リリースを確認し、
  閉じられるバナーで通知します。自動インストールはしません。
- **Ko-fi で支援**: `⚙` の隣にある ☕ Support ボタンから
  [ko-fi.com/youngminkim](https://ko-fi.com/youngminkim) を開けます。

### カスタマイズ

- **設定 (⚙)**: 一般、アカウント、アクティビティと通知、シンタックスカラー、
  ショートカット、設定ファイルの各セクションがあります。言語の選択、アカウントの
  管理、アクティビティログと Webhook の設定、エディターのシンタックスパレットの編集、
  ショートカットリファレンスの確認、`theme.toml` を直接開く操作ができます。
- **13 言語**: English、한국어、日本語、中文、हिन्दी、Español、Français、
  العربية、Português、Русский、Türkçe、Deutsch、Tiếng Việt。右下のステータスバー
  にあるセレクターから切り替えます。
- **埋め込み Web コンテンツからの保護**: すべてのバックエンドコマンドが呼び出し元の
  オリジンを検証するため、ブラウザペイン内のページが ymux の IPC を呼び出すことは
  できません。ymux は他のページにフレームとして埋め込まれると読み込みを拒否し、内蔵
  ブラウザは決められた少数の安全なショートカットのみを転送します。

## 設定

`config.toml` にはワークスペース、レイアウト、キャッシュされたシェルプロファイルが
保存されます。構造が変わるたびに (デバウンスあり) およびアプリ終了時に書き直されます。

`theme.toml` にはエディターのシンタックスカラーを含むカラーパレットが保存されます。
**設定 → シンタックスカラー** で編集するか、**設定 → 設定ファイル → 開く** で
ファイルを直接開けます。

どちらも ymux の設定ディレクトリに置かれます:

| プラットフォーム | パス |
|------------------|------|
| Windows          | `%APPDATA%\ymux\` |
| macOS            | `~/Library/Application Support/ymux/` |

macOS では同じディレクトリに、自動生成されたシェル統合ファイル (`zsh-init/`、
`bash-init.sh`) も置かれます。シェル検出のたびに書き直されるため、削除しても問題
ありません。

## プライバシー

ymux にはアカウント、アナリティクス、テレメトリがなく、サーバーも運用していません。
レイアウト、スクロールバック、ノート、設定はすべて PC 内に留まります。ymux が自発的に
行うリクエストは GitHub のアップデート確認だけで、使用量画面を使う場合は、それらの
CLI がすでにローカルに保存しているトークンを、そのトークンを発行したプロバイダーに
送る形で、Anthropic と OpenAI に利用枠を問い合わせるリクエストが加わります。アクティビティログをオンにすると Webhook の送信先や要約器のエンドポイントも指定でき、データは指定した先にのみ送られます ([アクティビティログと通知](#アクティビティログと通知) を参照)。詳しくは
[プライバシーポリシー](./packaging/microsoft-store/PRIVACY.md)をご覧ください。

## 開発

必要なもの: Rust (stable)、Node 20+、pnpm。

```sh
pnpm install
pnpm tauri dev          # run in dev mode
pnpm tauri build        # MSI on Windows, .app + .dmg on macOS
pnpm test               # fmt + tsc + clippy + tests
npx tsc --noEmit        # TypeScript type check
cargo clippy --workspace -- -D warnings
cargo test -p ytheme -p ypath
cargo test --no-default-features --lib -p ymux
```

`tauri build` は実行したホストに対応するインストーラを生成します (MSI バンドラは
Windows 専用、DMG バンドラは macOS 専用で、リリースワークフローもそうしています)。
Linux でも Rust クレートは `cargo check --no-default-features --lib --tests -p ymux`
がクリーンに通りますが、デスクトップアプリ自体は Linux 向けには配布していません。

メンテナー向け: Microsoft Store 用の MSIX パッケージは `scripts/package-msix.ps1` で
ビルドします。
[packaging/microsoft-store/README.md](./packaging/microsoft-store/README.md) を
参照してください。
