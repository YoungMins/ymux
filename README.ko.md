Windows와 macOS용 경량 tmux 스타일 터미널 멀티플렉서.

https://github.com/user-attachments/assets/705fff59-0bda-4460-a87f-d7ba6f50993a

ymux는 창 하나를 필요한 만큼의 터미널로 나누고, 레이아웃을 작업공간별로 저장하며,
셸, 스크롤백, AI 코딩 에이전트를 한곳에서 정리해 줍니다. Tauri 2 (Rust)와
xterm.js로 만들었고, Windows에서는 WebView2, macOS에서는 WKWebView 위에서
동작합니다.

## 설치

### Windows

**Microsoft Store**:
<https://apps.microsoft.com/detail/9N20Z9NKD2Q1>. 스토어 빌드는 시스템의 Evergreen
WebView2 런타임(Windows 11에 내장, Windows 10에서는 Windows Update로 제공)을
사용하며, `ymux` 앱 실행 별칭을 등록하므로 어느 터미널에서든 `ymux`를 실행할 수
있습니다.

**MSI**: [Releases](https://github.com/YoungMins/ymux/releases)에서
`ymux_*_x64_en-US.msi`를 받아 실행하세요. 인스톨러가 WebView2 부트스트래퍼를
포함하고 설치 경로를 `PATH`에 추가하므로, 어느 터미널에서든 `ymux`를 실행할 수
있습니다.

### macOS (Apple Silicon, macOS 11+)

[Releases](https://github.com/YoungMins/ymux/releases)에서
`ymux_*_macos_aarch64.dmg`를 받아 열고, ymux를 Applications로 끌어다 놓으세요.

앱은 ad-hoc 서명만 되어 있고 **공증(notarization)은 되어 있지 않습니다.** 그래서
처음 실행할 때 Gatekeeper가 "손상되었다" 또는 "확인되지 않은 개발자"라며
차단합니다. 다운로드 격리 속성을 한 번만 제거하면 됩니다:

```sh
xattr -dr com.apple.quarantine /Applications/ymux.app
```

## 기능

### 터미널과 레이아웃

- **저장되는 레이아웃**: 재귀적 가로 / 세로 분할. 각 pane은 자신의 셸, `cwd`,
  선택적 시작 명령을 기억합니다.
- **Pane 탭**: `Ctrl+Shift+T`로 포커스된 pane에 탭을 추가합니다. 숨겨진 탭도
  계속 실행됩니다.
- **현재 경로 계승**: pane을 분할하면 새 pane이 시작 디렉터리가 아니라 부모 셸이
  지금 있는 디렉터리에서 열립니다 (OSC 7 추적).
- **셸 자동 감지**: Windows에서는 `cmd.exe`, Windows PowerShell,
  PowerShell 7 (`pwsh`), Git Bash, WSL 배포판, 그리고 `vswhere`가 찾은 모든
  Visual Studio 설치본의 Developer Command Prompt / Developer PowerShell을
  찾습니다. macOS에서는 로그인
  셸과 함께 발견된 zsh / bash / fish (Homebrew 설치본 포함)를 보여줍니다.
  zsh와 bash는 자동 생성된 shim을 거쳐 시작되는데, 이 shim은 사용자 본인의
  dotfile을 먼저 읽은 뒤 OSC 7 훅을 덧붙입니다.
- **영속 스크롤백**: 각 pane의 버퍼가 (색상 포함) 다음 실행 때 흐린 *"세션 복원됨"*
  구분선 아래로 복원됩니다. **설정 → 일반**에서 켜고 끌 수 있습니다.
- **Pane 확대, 이름 변경, 검색**: `Ctrl+Shift+Z`는 나머지 pane을 숨기고,
  `Ctrl+Shift+R`은 포커스된 pane의 이름을 바꾸며, `Ctrl+F`는 터미널에 검색 바를
  엽니다 (Enter / Shift+Enter로 일치 항목 사이를 이동).
- **프롬프트 하단 고정**: 출력이 pane보다 짧으면 프롬프트가 하단에 붙고 출력이
  위로 쌓입니다. 기본값은 켜짐이며 **설정 → 일반**에서 끌 수 있습니다.
- **클릭 가능한 링크와 경로**: `Ctrl+클릭`하면 `http://` / `https://` 링크는 기본
  브라우저에서 열리고, 명령이 출력한 파일 경로는 OS 기본 프로그램으로 열립니다.
  실행 파일과 스크립트는 실행되지 않고 파일 관리자에서 표시만 됩니다.
- **텍스트와 이미지 붙여넣기**: `Ctrl+V`로 텍스트를 붙여넣습니다. 클립보드에
  이미지가 있으면 (예: `Win+Shift+S` 스크린샷) 자동 정리되는 임시 파일로 저장하고
  따옴표로 감싼 경로를 대신 입력합니다. 24시간 뒤 정리됩니다
  (`paste_image_retention_hours`).
- **파일 끌어다 놓기**: 파일이나 폴더를 터미널에 끌어다 놓으면 따옴표로 감싼
  경로가 커서 위치에 입력됩니다. Enter를 누르기 전에는 아무것도 실행되지
  않습니다.
- **Pane별 설정 (⚙)**: 사용자 지정 배경색과 HotKey 버튼 (터미널 위의 이름 붙은
  버튼에 단일 줄 또는 여러 줄 명령 지정)을 설정합니다.
- **트레이로 닫기**: 창을 닫으면 ymux가 트레이(Windows 알림 영역 / macOS 메뉴
  막대)로 숨고 모든 셸과 에이전트는 계속 실행됩니다. 트레이 아이콘을 클릭하거나
  ymux를 다시 실행하면 돌아옵니다 (ymux는 한 번에 하나만 실행됩니다). 종료는
  트레이 메뉴, macOS의 `Cmd+Q`, 또는 커맨드 팔레트의 **ymux 종료**로 하며,
  저장하지 않은 편집기가 있으면 먼저 묻습니다.

### 작업공간

- **번호가 붙은 작업공간**: `Ctrl+Alt+1` .. `Ctrl+Alt+9`로 처음 9개 사이를
  전환합니다. 작업공간 패널의 `+` 버튼으로 더 추가하고, 행의 `×`로 삭제합니다
  (마지막 하나는 삭제할 수 없음). 작업공간마다 자신의 레이아웃을 저장하며, 전환해도
  pane은 살아 있어서 REPL과 tail이 죽지 않습니다.
- **작업공간 패널**: 왼쪽의 접을 수 있고 스크롤되는 목록입니다. 이름을 더블클릭해
  바꾸고, 행을 끌어 순서를 바꿉니다. 활성 작업공간에는 테두리가 표시됩니다.
- **작업공간별 노트**: 각 작업공간 번호 옆의 노트 버튼, 그리고 활성 작업공간용
  `Ctrl+Alt+N`. `localStorage`에 저장됩니다.
- **Git worktree pane**: 커맨드 팔레트의 **"새 git worktree에서 pane 열기"**가
  브랜치 이름을 묻고, worktree를 만든 뒤 (기본 위치: 옆에 있는
  `.ymux-worktrees/<branch>` 디렉터리, `worktree_base_dir`로 변경 가능) 그 안에서
  터미널을 엽니다. pane을 닫거나 작업공간을 삭제할 때 worktree 제거 여부를
  묻습니다. 브랜치와 커밋은 건드리지 않습니다.

### AI 에이전트

- **에이전트 상태 한눈에 보기**: 각 터미널 pane이 출력 활동과 벨 / OSC 9 완료
  신호로 대기 / 실행 중 / 완료 / 주의 필요 상태를 보여주며, 색상 있는 pane 테두리와
  작업공간 행의 색조로 표시됩니다. 보고 있지 않은 곳에서 CLI가 끝나면 OS 알림과
  짧은 비프음이 울립니다 (설정에서 끌 수 있음).
- **런처**: 상단 **+** 메뉴에 설치된 에이전트 CLI, 셸, GUI pane이 나열됩니다.
  **에이전트 다시 검색**을 선택하면 목록을 새로 고칩니다.
- **에이전트 트리**: 작업공간 패널에 모든 pane과 탭이, 그 안에서 실행 중인
  에이전트와 함께 표시됩니다. 훅으로 감지하는 Claude Code 세션과 서브에이전트,
  그리고 가벼운 프로세스 스캔으로 감지하는 Codex, Gemini, aider 등 다른 CLI입니다.
  행을 클릭하면 해당 pane으로 이동합니다.
- **세션 재개**: Claude Code나 Codex가 실행 중인 pane에서 ymux를 재시작하면 같은
  대화를 이어서 재개합니다: `claude --resume <id>
  --dangerously-skip-permissions` (이미 승인한 항목을 다시 승인하지 않도록 항상
  붙습니다) 또는 `codex resume <id>`. 세션이 마지막으로 활동한 뒤 24시간 이내일
  때만 대상이 됩니다. 에이전트 추적을 켜지 않아도 동작하며, CLI가 디스크에 남기는
  자체 기록을 읽어서 찾습니다. 셸만 실행 중인 pane은 계속 스크롤백을 복원합니다.
- **Claude Code 훅 추적** (기본값 꺼짐, **설정 → 일반**): `~/.claude/settings.json`과
  모든 계정의 Claude 폴더에 사용자 수준 HTTP 훅을 추가합니다 (아래 "여러 계정"
  참고. 아직 없는 폴더는 그 안에서 터미널이 시작될 때까지 건너뜁니다). 켜져 있는
  동안에는 ymux 밖의 세션을 포함해 이 폴더들을 쓰는 이 컴퓨터의 *모든* Claude Code
  세션이 훅 이벤트 (프롬프트, 도구 입력과 출력)를 `127.0.0.1`의 ymux 포트로
  보냅니다. ymux는 자신의 pane에서 오지 않은 이벤트를 무시하며, 추적을 끄면 모든
  폴더에서 훅이 제거됩니다. 추적이 켜진 상태에서 ymux가 실행 중이 아니면 Claude
  Code가 해당 훅의 실패를 보고하므로 (예: "Stop hook error occurred"), ymux를
  제거하거나 계정을 삭제하거나 계정을 모르는 이전 버전으로 되돌리기 전에 추적을
  끄세요 (그렇지 않으면 계정 폴더에 훅이 남습니다). ymux는 보조 바이너리를 함께
  설치하지 않습니다.

#### 자동 계속 (Claude Code)

터미널별로 pane의 ⚙ 대화상자 또는 명령 팔레트("이 창의 자동 계속 켜기/끄기")에서
켭니다. 켜면 pane 제목에 **AUTO** 배지가 나타나고, 마우스를 올리면 최근 답변이
표시됩니다. 켜져 있는 동안 ymux가 Claude Code의 객관식 질문(`AskUserQuestion`)에
직접 답합니다. 라벨이 "(Recommended)"로 끝나는 선택지를 고르고 (다중 선택 질문은
해당하는 선택지를 모두), 추천 선택지가 없는 질문이 하나라도 있으면 그 질문을
거부하고 Claude가 직접 선택하도록 안내합니다. Claude Code 훅 추적(설정 → 일반)이
필요하고 Claude Code에서만 동작하며, 실행 중에만 유효합니다. 재시작하거나 터미널을
닫으면 다시 꺼집니다. 주의: 추천 선택지는 Claude의 제안일 뿐 항상 옳지는 않으므로,
잘못된 답을 되돌리기 쉬운 작업에만 사용하세요.

#### 사무실 보기

상단 바의 사무실 버튼(또는 `Ctrl+Shift+O`)을 누르면 현재 작업공간을 픽셀 아트
사무실로 볼 수 있습니다. pane(또는 탭 묶음)마다 나눈 모양 그대로 방이 되고 방
사이에는 복도가 생기며, 탭마다 책상이 놓입니다. 에이전트는 CLI 색깔의 슬라임입니다
(Claude Code 주황, Codex 짙은 회색, Gemini 파랑). 작업 중에는 책상에서 들썩이며 쓰는
도구를 말풍선에 띄우고, 확인이 필요하면 길쭉하게 서서 통통 튀고, 끝나면 커피를 마시고,
대기 중에는 녹아내려 낮잠을 잡니다. 서브에이전트는 새싹 달린 꼬마 슬라임으로 들어와
앞줄에서 일하다가, 끝나면 리드에게 보고하고 나갑니다.

상단의 테마 선택에서 같은 배치를 사무실, 동굴, 성, 목장, 우주정거장, 해저, 설원 마을,
사막 신전으로 바꿀 수 있습니다. 책상은 돌판, 건초 더미, 콘솔 등으로 바뀌고, 그 위의
수정·랜턴·화면이 pane 상태에 따라 빛납니다. 고른 테마는 기억됩니다.

**모험가.** 계정마다 RPG 영웅이 됩니다. 사용량 보기의 계정별 전체 기록 토큰 합계(Claude
Code와 Codex 합산)가 경험치이고, 1억 토큰마다 레벨이 하나 오릅니다. 사무실 상단의
*⚔ 모험가*를 누르면 모험가 길드가 열려 계정별 레벨, 경험치 바, 직업(전사·마법사·도적·
성직자·고양이)과 외형(슬라임 또는 인간형 모험가, 머리색은 에이전트 색)을 보고 고를 수 있습니다. 사무실의 에이전트는 그 계정의 직업 장비와 레벨
배지를 달고, 레벨에 따라 10단계로 모습이 바뀝니다. Lv 0 평상복, Lv 1 기본 장비, Lv 3 완전한
장비, Lv 5 보석, Lv 10 직업 무기(검·지팡이·단검·성스러운 지팡이·생선), Lv 20 망토(슬라임은
띠), Lv 30 황금 장비, Lv 50 날개, Lv 75 반짝이는 오라, Lv 100 전설의 왕관과 무지갯빛 오라와
주위를 도는 별. 사무실을 보고 있을 때 레벨이 오르면 배너로 알려 줍니다.

- **완료** — 에이전트가 만세 점프를 하며 색종이가 터지고, 그 pane을 열어 볼 때까지 방
  문 옆에 깃발이 꽂혀 있습니다.
- **우편** — ymux가 한 곳에서 다른 곳으로 넘기는 일(팬아웃 프롬프트, 변경 검토 의견,
  커밋 요청)은 복도를 지나 배달되어 방 우편함에 꽂힙니다. 에이전트가 시작하기 전에는
  봉한 편지, 작업 중에는 열린 편지이고, 그 턴이 끝나면 사라집니다. 우편함에 마우스를
  올리면 내용을 볼 수 있습니다.
- **게시판** — 로비의 코르크 게시판에 완료와 전달마다 메모가 붙습니다. 누르면 목록이
  열리고, 항목을 누르면 그 pane으로 이동합니다.

방·책상·슬라임을 누르면 그 자리에 터미널 창이 열려 실시간 화면을 볼 수 있습니다. 메뉴에
답하는 키 버튼(화살표, Enter, Esc, Tab, 1–3)과 프롬프트 입력창(Enter로 보내기,
Shift+Enter로 줄바꿈)이 있습니다. 방을 더블클릭하거나 *터미널 열기*를 누르면 그 pane으로
이동하고, 깃발·우편함·게시판 메모는 바로 이동합니다. `Esc`는 창을 먼저 닫고, 한 번 더 누르면
사무실을 닫습니다. 터미널은 그동안에도 계속 실행됩니다. 깃발, 우편,
게시판은 앱을 켜 둔 동안만 유지됩니다.

#### 여러 계정

웹사이트에서 여러 계정에 로그인하듯 Claude Code나 Codex 로그인을 여러 개
나란히 쓸 수 있습니다. 상단 바의 **+** 를 눌러 Claude Code나 Codex를 고르면
어느 계정으로 실행할지 묻습니다 — 기본 로그인(`~/.claude`, `~/.codex`), 추가해 둔
계정, 또는 **+ 새 계정 추가…**. 새 계정은 이름만 정하면 되고, ymux가 설정 폴더 아래에
계정별 로그인 폴더를 따로 만들어 주며, 그 계정으로 처음 실행할 때 에이전트가 로그인을
요청합니다. **설정 → 계정**에서는 이름·색상 변경과 삭제를 할 수 있습니다(기존 로그인
폴더를 직접 지정하려면 "고급"을 펼치세요). 계정을 삭제하면 ymux가 그 계정용으로
만든 로그인 폴더도 함께 삭제되므로, 다시 추가하면 로그인을 새로 해야 합니다. 직접
지정한 폴더는 절대 삭제하지 않습니다. 계정은 pane의 ⚙ 대화상자에서 터미널별로
고르거나, 작업공간 패널에서 작업공간 행을 우클릭해 작업공간 전체의 기본값으로 지정할
수도 있습니다. 계정이 적용된 터미널은
제목에 색상 배지가 표시됩니다. 변수는 터미널이 시작될 때 설정되므로 변경은
이후에 시작하는 터미널부터 적용됩니다(실행 중인 셸은 기존 계정을 유지하며, 다시
시작하기 전까지 배지가 흐리게 보입니다). 토큰 사용량은 설정된 모든 계정의 폴더를 읽고,
세션 재개는 터미널이 실행된 계정의 폴더에서 찾습니다.

#### 변경 사항 검토

에이전트가 한 작업을 diff로 읽고, 줄 단위 의견을 곧바로 에이전트에게 보낼 수
있습니다. 커맨드 팔레트의 **"변경 사항 검토"**, Git pane의 **변경 사항 검토** 버튼이나
worktree 행, 팬아웃 비교 화면의 **검토**로 엽니다. 저장소(또는 worktree) 하나를
대상으로 하는 전체 창 오버레이이며, Esc나 ✕로 닫습니다. 숨겨진 동안에도 유지되고,
레이아웃에는 아무것도 저장되지 않습니다.

- **파일과 hunk**: 왼쪽에 변경된 파일 목록, 오른쪽에 선택한 파일의 hunk가 **통합**
  또는 **분할** 보기로 표시됩니다. 추적되지 않는 파일은 추가된 내용으로 보이고,
  바이너리 파일은 표시되며, 아주 큰 diff는 잘립니다 (파일 3000개, 파일당 패치
  512 KiB).
- **비교 대상**: `HEAD`(커밋되지 않은 모든 변경, 기본값) 또는 브랜치(merge-base와
  비교). **CR 무시**는 CRLF 차이로 생기는 잡음을 숨깁니다. 창이 다시 포커스를 받을
  때와 에이전트가 끝났을 때 새로 고쳐집니다.
- **의견**: 줄을 클릭해 의견을 남기고, Shift+클릭으로 범위를 지정합니다. 의견은
  오버레이 안에만 있으며 (닫으면 사라짐), 코드가 바뀌어 위치를 못 찾으면 엉뚱한
  줄을 가리키는 대신 "위치 바뀜 또는 삭제됨"으로 표시됩니다.
- **에이전트에게 보내기**: 의견들을 (각각 파일, 줄 번호, 앞뒤 몇 줄과 함께) 그
  저장소에서 실행 중인 에이전트의 터미널에 붙여넣습니다. 여러 에이전트가 맞으면
  고르게 합니다. **"보낸 뒤 Enter 입력"을 켠 경우에만** Enter까지 눌러 주며, 기본값은
  꺼짐입니다. 에이전트가 권한 요청이나 폴더 신뢰 확인에 대한 답을 기다리는 중이거나
  터미널이 붙여넣기를 받지 않을 때는 붙여넣지 않고, 에이전트가 아예 없으면 대신
  클립보드에 복사합니다. 32 KiB를 넘으면 먼저 확인을 묻습니다.

#### 수신함 (확인이 필요한 pane)

작업공간 바의 종 아이콘에는 확인이 필요하거나 (에이전트가 질문하거나 승인을
요청함) 자리를 비운 사이 끝난 pane의 수가 배지로 표시됩니다. 누르면 목록 (확인이
필요한 항목이 먼저)과 이미 읽은 최근 20개가 나오고, 행을 고르면 해당 pane으로
이동합니다. `Ctrl+Shift+U`는 확인이 필요한 다음 pane으로 바로 이동합니다. pane에
포커스를 두면 읽음 처리됩니다.

#### 팬아웃

프롬프트 하나를 여러 에이전트에게, 각자의 git worktree에서 실행하게 하고 결과를
비교합니다. 커맨드 팔레트에서 **"프롬프트를 여러 에이전트에 보내기…"**를 실행하세요.

| 항목 | 의미 |
|------|------|
| 저장소 / 기준 브랜치 | worktree를 만들 출발점 |
| 에이전트 | 1~8개 레인. 각각 Claude Code 또는 Codex이며 계정을 고를 수 있음 |
| 브랜치 접두사 | 기본값 `fanout`. 브랜치 이름은 `<접두사>/<실행ID>-<에이전트>-<번호>` |
| 프롬프트 | 최대 32 KiB, 모든 레인에 전달 |
| 새 작업공간에서 열기 | 레인을 새 작업공간에 배치 |
| Enter 자동 입력 | 기본값 켜짐. 끄면 프롬프트만 입력하고 Enter는 직접 누름 |

레인마다 새 브랜치와 worktree (worktree pane과 같은 위치: `worktree_base_dir`을
지정하지 않으면 `.ymux-worktrees`)가 만들어지고, 일반 에이전트 명령을 실행하는
터미널이 열립니다. 팬아웃은 권한 우회 플래그를 **추가하지 않습니다**. 레인이 둘이면
나란히, 넷까지는 격자로, 그보다 많으면 탭으로 배치합니다. 프롬프트는 에이전트가
준비된 뒤에 붙여넣으며 명령줄에는 넣지 않습니다. 에이전트가 폴더 신뢰 확인 같은
질문을 띄우면 그 pane에서 답할 때까지 해당 레인은 기다립니다. 90초 안에 준비되지
않으면 **지금 보내기** 또는 **프롬프트 복사**를 고를 수 있습니다. 시작에 실패한
레인은 알려 주고, 이미 만든 것은 그대로 둡니다.

**"팬아웃 레인 비교…"**는 레인별 상태, 변경된 파일 (+/−), 앞선 커밋 수를 보여 주며
**검토** (팬아웃 기준과의 diff 열기), **창으로 이동**, **유지…**를 제공합니다. 유지는
병합하지 않습니다. 병합 명령을 보여 주고 메인 worktree에 입력만 해 두며 (실행은
직접), 나머지 레인 정리를 제안합니다. 정리는 확인한 worktree를 제거하고 브랜치는
`git branch -d`로 지우므로 병합되지 않은 브랜치는 남습니다.

### 활동 로그와 알림

선택 기능이며 **기본값은 꺼짐**입니다: **설정 → 활동 및 알림**. ymux는 에이전트가
한 일을 로컬 로그로 남기고, 턴이 끝나거나 에이전트가 사용자를 필요로 할 때 채팅이나
웹훅으로 짧은 보고를 보낼 수 있습니다. 모델 토큰은 쓰지 않으며, 목적지를 추가하지
않으면 PC 밖으로 나가는 것은 없습니다.

**기록하는 것.** 프롬프트, 도구 호출, 권한 요청, 끝난 턴마다 JSON 한 줄입니다.
Claude Code 이벤트는 위의 훅 추적에서 오므로 훅 추적이 켜져 있어야 합니다. Codex 턴은
CLI 자체의 세션 파일에서 읽으며, ymux가 이미 추적 중인 터미널에 대해서만 읽습니다.
도구 기록에는 도구 이름, 건드린 파일 경로(잘림), 잘린 명령줄, 종료 코드가
남습니다. 끝난 턴에는 소요 시간, `git diff --stat`에서 얻은 변경 파일과 +/− 수,
테스트 통과 여부가 더해집니다. **기록하지 않는 것**: 파일 내용, 도구 출력, 전체
대화 기록, 그리고 **프롬프트 내용 기록**을 켜지 않는 한 프롬프트와 어시스턴트의
답변 텍스트.

**마스킹.** 디스크, 요약기, 웹훅으로 가기 전에 모두 마스킹합니다. 개인 키 블록,
벤더 토큰 (`sk-…`, `ghp_…`, `xox…`, AWS·Google 키), JWT, `Bearer` 헤더,
`user:pass@` URL, 채팅 웹훅 URL, `key=value` 비밀값이 대상입니다. 패턴 매칭이며
완벽을 보장하지 않습니다.

**저장.** ymux 설정 디렉터리 ([설정](#설정) 참고)의 `activity/YYYY-MM-DD.jsonl`에
하루에 파일 하나씩 저장합니다. 로그는 14일 뒤 삭제되고 (**로그 보관**),
전체는 200 MiB (`max_total_mb`), 하루는 20 MiB로 제한되며 한도를 넘으면 도구 기록부터
버립니다. **로그 폴더 열기**와 **로그 지우기**는 같은 섹션에 있고, 이 섹션에서
최근 턴도 볼 수 있습니다.

**요약.** 턴이 끝날 때 위의 사실 정보로 만들며, 대화 기록으로 만들지 않습니다.

- **기본 규칙** (기본값): 모델 없이 오프라인으로 동작합니다. 영어, 한국어, 일본어
  템플릿이 있습니다 (그 외 언어는 영어).
- **Ollama**: **모델 불러오기**로 받아 둔 모델을 나열해 고릅니다. 작은 모델이면
  충분합니다. [Ollama](https://ollama.com)를 설치한 뒤 예를 들어:

  ```sh
  ollama pull gemma3:1b
  ```

  기본 엔드포인트는 `http://127.0.0.1:11434`입니다.
- **OpenAI 호환** (LM Studio 등): 엔드포인트, 모델, API 키. 키는 암호화되어
  저장되고 다시 표시되지 않습니다.

엔드포인트는 이 컴퓨터에 있어야 합니다. 이름을 해석한 뒤 주소를 검사하므로 다른
곳을 가리키는 이름은 거부됩니다. **원격 엔드포인트 허용**을 켜면 이 제한이 풀리며,
그때부터 턴 텍스트가 해당 서버로 전송됩니다. 요청은 기본 20초 뒤 시간 초과되고,
실패하면 기본 규칙 요약으로 대체됩니다. **요약 테스트**로 모델의 응답을 확인할 수
있습니다.

**웹훅 목적지.** 원하는 만큼 (최대 20개) 추가할 수 있고, 각각 설정이 따로 있습니다.

| 형식 | 비고 |
|------|------|
| JSON (일반) | 서명됨 (아래), 파일을 첨부하면 multipart |
| Slack | 수신 웹훅 블록. 첨부 파일은 이름만 나열 |
| Discord | 임베드. 파일은 Discord 크기 제한 안에서 최대 10개 업로드 |
| Microsoft Teams | Workflows 어댑티브 카드. 첨부 파일은 이름만 나열 |

목적지별 설정: 사용, 이름, URL, 이벤트 (**턴 완료**, **확인 필요**), 상세 수준
(**요약** 또는 **전체**: pane, 계정, 작업 폴더, 파일, 테스트 결과 추가),
**프롬프트 포함** (꺼짐), 묶음 대기 시간 (기본 10초, 한 메시지에 최대 10개 이벤트),
선택 사항인 HMAC 비밀값. **테스트 전송**과 **페이로드 미리보기**로 나갈 내용을 볼 수
있습니다. 전송에 실패하면 디스크 대기열 (목적지당 200개 또는 5 MiB)에 쌓고
백오프로 재시도합니다 (5초에서 시작해 두 배씩 최대 30분, 8회, `Retry-After`
준수). 리디렉션은 따라가지 않습니다. **웹훅 URL은 자격 증명입니다**. 가진 사람은
누구나 그 채널에 글을 올릴 수 있으므로, ymux는 URL과 비밀값, API 키를
`config.toml`이 아니라 `secrets.json`에 암호화해서 (Windows DPAPI, macOS는 `0600`
파일) 저장하고 다시 보여 주지 않습니다. `http://` URL은 보고서가 암호화 없이 네트워크를
지나므로 경고가 표시됩니다.

JSON 형식 검증. 요청마다 `X-Ymux-Timestamp` (Unix 초), `X-Ymux-Delivery` (고유
ID)가 붙고, 비밀값을 설정했다면 `X-Ymux-Signature: sha256=<hex>`가 붙습니다.
값은 `hex(HMAC-SHA256(비밀값, 타임스탬프 + "." + 본문))`입니다. multipart 요청에서는
첫 번째 파트인 `payload`가 서명 대상 본문입니다.

```python
import hmac, hashlib

def verify(secret: str, timestamp: str, body: bytes, signature: str) -> bool:
    mac = hmac.new(secret.encode(), timestamp.encode() + b"." + body, hashlib.sha256)
    return hmac.compare_digest("sha256=" + mac.hexdigest(), signature)
```

타임스탬프가 현재와 크게 다른 요청과 중복된 전송 ID도 거부하세요.

**첨부 파일.** 목적지별 설정이며 기본값은 꺼짐입니다. 턴이 만든 파일을 보고서와 함께
보냅니다. 후보는 턴이 터미널의 저장소(또는 worktree) 안에서 만들거나 바꾼 파일, 그리고
턴 동안 보고서 폴더 (기본 `.ymux/report`, **리포트 폴더**)에 둔 파일입니다. 허용
형식은 직접 고르며 (기본값은 없음) 이미지 (png, jpg, gif, webp), PDF, 오디오 (mp3,
wav, ogg), 비디오 (mp4, webm), Office 문서 (docx, xlsx, pptx), 텍스트 (md, txt,
csv)입니다. 기본 제한은 파일당 8 MB, 전체 8 MB, 4개이며 (상한은 25 MB, 10개),
일반 파일이고 심볼릭 링크가 아니며 하드 링크가 하나뿐이고, 내용이 확장자와 일치하며
(비밀값이 들어 있는 텍스트 파일은 거부), 이름이 민감하지 않은 (`.env*`, `*.pem`,
`*.key`, `id_rsa*`, `*secret*`, `*credentials*` 등이나 `.git`, `.ssh`, `.aws` 아래가
아닌) 파일만 보냅니다. 보내는 순간에 열린 파일 기준으로 다시 검사합니다. 조건에 맞지
않거나 제한을 넘는 파일은 이름만 나열하며, 이 때문에 전송 자체가 실패하지는 않습니다.

**이전 버전으로 되돌릴 때.** 0.13.9 이하 버전은 이 기능을 모릅니다. 그 버전을 열면
`config.toml`의 웹훅 목록이 사라지므로 (암호화된 비밀값은 `secrets.json`에 남음)
목적지 설정을 미리 기록해 두세요.

### 사이드 패널: 파일과 사용량

모든 작업공간이 공유하는 오른쪽 패널 하나입니다. 상단의 아이콘으로 두 화면을
전환하며, 숨겨져 있는 동안에도 각 화면은 상태를 유지합니다. 열림 상태, 화면, 너비는
저장되고, 왼쪽 가장자리를 끌어 너비를 조절합니다.

- **파일**: `Ctrl+Shift+E`로 토글합니다. `cd`로 이동할 때마다 활성 pane의 작업
  디렉터리를 따라갑니다. 파일에서 Enter를 누르면 재사용되는 편집기 탭에서 열리고,
  목록 아래에 선택한 파일이나 폴더의 미리보기가 있습니다 (`Tab`으로 표시/숨김).
- **사용량**: 패널의 사용량 아이콘으로 전환하거나 (도구 모음의 사이드 패널 버튼은 마지막 화면을 다시
  엽니다) 커맨드 팔레트에서 엽니다. 다음을 보여줍니다:
  - Claude Code와 Codex의 로컬 토큰 수. 세션 로그에서 읽으며, 최근 5시간, 최근 7일,
    전체 기록 기간을 AI 제공자, 모델, 프로젝트, 계정별로 묶어 보여주고, 선택한
    기간의 합계 줄을 표시합니다 (**전체 기록 사용량**은 전체 합계).
  - 5시간 / 주간 남은 한도와 초기화까지의 카운트다운. 남은 양 또는 사용량 중
    원하는 쪽으로 표시합니다. 한도는 해당 CLI가 이미 PC에 저장해 둔 로그인 토큰으로
    Anthropic과 OpenAI에서 직접 가져옵니다 ([개인정보 보호](#개인정보-보호) 참조).

  로컬 합계는 표시되는 동안 10초마다 갱신되고, 계정 한도는 최대 1분에 한 번만
  가져옵니다(실패하면 더 빨리 다시 시도하고, ↻ 버튼은 최대 30초마다 한 번이며,
  그 외에는 마지막 결과를 보여줍니다). 로컬 합계에는 웹 채팅과 다른 기기가 포함되지
  않고 이전에 쓰던 계정이 포함될 수 있으므로, 구독 한도와 같지 않습니다. 한도를
  가져오지 못하면 기록된 스냅샷을 오래된 값이라고 표시해 보여줍니다.

### 내장 pane

터미널 옆에 ymux가 직접 그리는 화면입니다. 모두 포커스된 pane을 분할해 그 작업
디렉터리에서 열립니다:

- 터미널의 오른쪽 클릭 메뉴: 파일, 편집기, Git
- 상단 바의 **+** 런처: 파일, Git, 브라우저 (**+ 브라우저** 버튼으로도 추가)
- 커맨드 팔레트: **분할: 파일 창**, **분할: 편집기 창**, **분할: git 패널**

편집기는 사이드 패널에서 파일을 골라 Enter를 눌러도 열립니다.

| Pane | 기능 |
|------|------|
| **파일** | 탐색, 미리보기, 이름 변경, 새로 만들기, 다중 선택, 복사/이동, 덮어쓰기 확인, 휴지통으로 삭제 (확인 후) |
| **편집기** | 구문 강조 텍스트 편집기: 저장, 찾기/바꾸기, 줄 이동, CRLF/BOM 보존, 저장 안 한 변경 확인, 충돌 방지용 임시 초안, 외부 변경 감지 |
| **Git** | 커밋 그래프, 브랜치 목록과 체크아웃, worktree 추가/제거 (확인 후), **변경 사항 검토** (diff 검토) |
| **브라우저** | URL 바와 뒤로 / 앞으로 / 새로고침이 있는 iframe 브라우저. URL은 전환과 재시작 후에도 유지됩니다 |

> **참고:** 브라우저 pane은 HTML `<iframe>`이라 `X-Frame-Options`나 CSP
> `frame-ancestors`로 임베드를 거부하는 사이트 (예: github.com, google.com)는
> 로드되지 않습니다. 로컬 개발 서버, Storybook, 사내 대시보드, 문서용이며 일반 웹
> 브라우징용이 아닙니다.

### 생산성

- **커맨드 팔레트**: `Ctrl+Shift+P`. 이름이나 단축키로 모든 내장 동작을 퍼지
  매칭으로 찾습니다. **탭 이름 변경**, **다른 탭 닫기**, **새 작업공간**,
  **작업공간 삭제**, 작업공간 이름 변경, 편집기 / 파일 / git pane 분할처럼
  팔레트에서만 쓸 수 있는 동작도 있습니다.
- **시스템 모니터**: 하단 상태 바에 CPU / RAM / GPU / 디스크 / 네트워크를 2초마다
  표시합니다. 70%에서 주황, 90%에서 빨강으로 바뀝니다.
- **업데이트 알림**: 6시간마다 백그라운드에서 GitHub 릴리스를 확인해 닫을 수 있는
  배너로 알려줍니다. 자동으로 설치하지는 않습니다.
- **Ko-fi 후원**: `⚙` 옆의 ☕ Support 버튼이
  [ko-fi.com/youngminkim](https://ko-fi.com/youngminkim)을 엽니다.

### 사용자 지정

- **설정 (⚙)**: 일반, 계정, 활동 및 알림, 구문 색상, 단축키, 설정 파일 섹션이
  있습니다. 언어를 고르고, 계정을 관리하고, 활동 로그와 웹훅을 설정하고, 편집기의
  구문 팔레트를 수정하고, 단축키 참조를 보거나, `theme.toml`을 바로 열 수 있습니다.
- **13개 언어**: English, 한국어, 日本語, 中文, हिन्दी, Español, Français,
  العربية, Português, Русский, Türkçe, Deutsch, Tiếng Việt. 오른쪽 하단 상태 바의
  선택기에서 바꿉니다.
- **내장 웹 콘텐츠로부터 격리**: 모든 백엔드 명령이 호출자의 출처를 검사하므로
  브라우저 pane 안의 페이지가 ymux의 IPC를 호출할 수 없습니다. ymux는 다른 페이지에
  프레임으로 삽입되면 로드를 거부하며, 내장 브라우저는 정해진 소수의 안전한
  단축키만 전달합니다.

## 키보드 단축키

macOS에서는 아래의 모든 `Ctrl`이 `Cmd`로 바뀝니다. 그래야 `Ctrl`이 셸 본래의
용도 (`Ctrl+C`, `Ctrl+D`, `Ctrl+R`)로 남습니다. 예외는 표에 적힌 두 가지입니다.
pane 순환은 macOS가 `Cmd+Tab`을 앱 전환기로 쓰기 때문에 `Ctrl+Tab`을 유지하고,
작업공간 전환은 `Alt`를 뺍니다.

| 단축키 (Windows)            | macOS              | 동작                                 |
|-----------------------------|--------------------|--------------------------------------|
| `Ctrl+Shift+H`              | `Cmd+Shift+H`      | pane 가로 분할                       |
| `Ctrl+Shift+V`              | `Cmd+Shift+V`      | pane 세로 분할                       |
| `Ctrl+Shift+W`              | `Cmd+Shift+W`      | 포커스된 pane 닫기                   |
| `Ctrl+Shift+T`              | `Cmd+Shift+T`      | 포커스된 pane에 새 탭                |
| `Ctrl+Shift+[` / `]`        | `Cmd+Shift+[` / `]` | pane 안에서 이전 / 다음 탭          |
| `Ctrl+Shift+Z`              | `Cmd+Shift+Z`      | 포커스된 pane 확대 / 원복            |
| `Ctrl+Shift+U`              | `Cmd+Shift+U`      | 확인이 필요한 다음 창으로 이동       |
| `Ctrl+Shift+O`              | `Cmd+Shift+O`      | 사무실 보기 전환                     |
| `Ctrl+Shift+←/→`            | `Cmd+Shift+←/→`    | 이전 / 다음 pane과 자리 바꾸기       |
| `Ctrl+Shift+R`              | `Cmd+Shift+R`      | 포커스된 pane 이름 변경              |
| `Ctrl+Shift+P`              | `Cmd+Shift+P`      | 커맨드 팔레트 열기                   |
| `Ctrl+Alt+N`                | `Cmd+Opt+N`        | 활성 작업공간의 노트 토글            |
| `Ctrl+Shift+E`              | `Cmd+Shift+E`      | 사이드 패널 토글 (파일 화면)         |
| `Ctrl+V`                    | `Cmd+V`            | 클립보드 텍스트 붙여넣기 (이미지 → 임시 파일 경로) |
| `Ctrl+F`                    | `Cmd+F`            | 터미널 스크롤백 검색 (편집기 pane에서는 찾기 / 바꾸기) |
| `Ctrl+S`                    | `Cmd+S`            | 파일 저장 (편집기 pane)              |
| `Ctrl+G`                    | `Cmd+G`            | 줄로 이동 (편집기 pane)              |
| `Ctrl++` / `Ctrl+-`         | `Cmd++` / `Cmd+-`  | 터미널 글자 크기 확대 / 축소         |
| `Ctrl+0`                    | `Cmd+0`            | 터미널 글자 크기 초기화              |
| `Ctrl+Tab`                  | `Ctrl+Tab`         | 다음 pane으로 포커스 이동            |
| `Ctrl+Shift+Tab`            | `Ctrl+Shift+Tab`   | 이전 pane으로 포커스 이동            |
| `Ctrl+Alt+1` .. `Ctrl+Alt+9` | `Cmd+1` .. `Cmd+9` | 작업공간 전환                       |
| URL/경로 위에서 `Ctrl+클릭` | `Cmd+클릭`         | 링크 또는 출력된 파일 경로를 OS 기본 프로그램으로 열기 |
| 작업공간 이름 더블클릭      | —                  | 작업공간 이름 변경                   |
| 작업공간 행 끌기            | —                  | 작업공간 순서 변경                   |
| 터미널에서 마우스 오른쪽 클릭 | —                | 컨텍스트 메뉴: 복사/붙여넣기, 분할, 파일 / 편집기 / Git pane 열기 |
| `⚙` 버튼 (도구 모음)        | —                  | 설정 열기 (일반, 계정, 활동 및 알림, 구문 색상, 단축키, 설정 파일) |

사용량 화면에는 단축키가 없습니다. 패널의 사용량 아이콘이나 커맨드
팔레트를 사용하세요.

## 설정

`config.toml`에는 작업공간, 레이아웃, 캐시된 셸 프로필이 저장됩니다. 구조가 바뀔
때마다 (디바운싱 적용) 그리고 앱을 닫을 때 다시 쓰입니다.

`theme.toml`에는 편집기의 구문 색상을 포함한 색상 팔레트가 저장됩니다.
**설정 → 구문 색상**에서 편집하거나 **설정 → 설정 파일 → 열기**로 파일을 바로 열
수 있습니다.

두 파일 모두 ymux 설정 디렉터리에 있습니다:

| 플랫폼   | 경로 |
|----------|------|
| Windows  | `%APPDATA%\ymux\` |
| macOS    | `~/Library/Application Support/ymux/` |

macOS에서는 같은 디렉터리에 자동 생성된 셸 통합 파일 (`zsh-init/`,
`bash-init.sh`)도 들어갑니다. 셸을 감지할 때마다 다시 쓰이므로 지워도 괜찮습니다.

## 개인정보 보호

ymux에는 계정, 분석, 텔레메트리가 없으며 서버도 운영하지 않습니다. 레이아웃,
스크롤백, 노트, 설정은 모두 PC에만 남습니다. ymux가 자발적으로 보내는 요청은 GitHub
업데이트 확인뿐이며, 사용량 화면을 쓰는 경우에는 Anthropic과 OpenAI에 한도를 조회하는
요청이 추가됩니다. 이 요청은 해당 CLI가 이미 로컬에 저장해 둔 토큰을 그 토큰을 발급한
제공자에게 보냅니다. 활동 로그를 켜면 웹훅 목적지와 요약기 엔드포인트도 지정할 수 있으며, 데이터는 사용자가 지정한 곳으로만 갑니다 ([활동 로그와 알림](#활동-로그와-알림) 참고). 전체 [개인정보 처리방침](./packaging/microsoft-store/PRIVACY.md)을
참고하세요.

## 개발

필요한 것: Rust (stable), Node 20+, pnpm.

```sh
pnpm install
pnpm tauri dev          # run in dev mode
pnpm tauri build        # MSI on Windows, .app + .dmg on macOS
pnpm test               # fmt + tsc + clippy + tests
npx tsc --noEmit        # TypeScript type check
cargo clippy --workspace -- -D warnings
cargo test -p ytheme -p ypath
cargo test --no-default-features --lib -p ymux
```

`tauri build`는 실행한 호스트에 맞는 인스톨러를 만듭니다 (MSI 번들러는 Windows
전용, DMG 번들러는 macOS 전용이며, 릴리스 워크플로가 그렇게 동작합니다). Linux에서도
Rust 크레이트는 `cargo check --no-default-features --lib --tests -p ymux`가 깨끗하게
통과하지만, 데스크톱 앱 자체는 Linux로 배포하지 않습니다.

메인테이너용: Microsoft Store MSIX 패키지는 `scripts/package-msix.ps1`로 빌드합니다.
[packaging/microsoft-store/README.md](./packaging/microsoft-store/README.md)를
참고하세요.
